# Разворачивание
Для разворачивания требуется Docker и make.
Из корня папки в терминал ввести 
```make up```

# Комментарии
Это не продакш решение. Это решение, которое я бы дальше докручивал.
Проект состоит из трех сервисов: база(postgresql), миграции, бэк
Для удобства разработки использовал swaggo и он доступен по 
```http://localhost:8081/swagger/index.html#/```
Для того что бы постоянно не курлиться.

Что я бы сделал иначе:
1) Для кэша использовал бы Redis. Вместо него используется простенькое хранилище на самом сервисе
2) Для файлов и json я бы поднял бы s3. Либо по облаку, либо self-host через minio. 
3) Учитывал бы лимит на ответы на api.
4) Cделал бы нормальный gracefull shutdown
5) Сделал бы gateway на nginx. Что бы допустим сервис фронта(если бы он был) шел через него на бэк
Из-за нехватки времени сложновато было все сделать. Совмещая с работой))
Что не успел сделать:
1) Возможность присвоения определенному пользователю файла(grant)
2) Разделение доступов к файлам (все файлы доступны всем)
3) Не точности в api в части получения файлов
4) head запросы 
5) Не сделал запросы на создание новых миграций
6) Асинхронность при работе с кэшом
7) Тесты (в целом исходя из архитектуры это можно достаточно просто сделать)
8) Прикрутить нормальные логи, мб метрики
